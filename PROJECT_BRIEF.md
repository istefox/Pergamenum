## What we are building

Pergamenum, a native macOS app for Stefano's personal use, fully offline, that merges
three tools into one:

1. A **local markdown note vault** with wikilinks and backlinks (Obsidian model),
   compatible with the existing "Labs" vault and conformant to the `harness-system`
   conventions.
2. A **Workspace**, an infinite spatial canvas where notes, PDFs, images, emails and
   links float as resizable cards, organised into boards that map 1:1 onto real
   folders on disk (VisualOS model, JSON Canvas 1.0 file format).
3. An **integrated task and calendar system**: daily notes, `>date` scheduling,
   timeblocking, two-way Calendar and Reminders integration through EventKit, and
   tasks linkable to both notes and canvases.

**Definition of done for v1**: with no internet connection, Stefano can open the Labs
vault, write a daily note with tasks, drag a PDF onto the Workspace where it appears
as a resizable image, attach an email to a note (`.eml` file or `message://` link)
that opens in one click, link a task to a note or a canvas and navigate that link in
both directions, schedule a task on a date so it surfaces in that day's note, and see
and create Apple Calendar events from the app timeline.

## Why

One tool instead of three, with the data staying in plain files that outlive the app.
The existing harness taxonomy becomes the native schema rather than a convention
applied by hand.

## Scope

**In scope (v1):** everything in SPEC §4 to §12 - vault and taxonomy, markdown editor
with applied styling, Workspace with the 11-tool sidebar, PDF and email and URI
cards, spacebar Quick Look, task syntax and views, daily notes and EventKit,
`pergamenum://` URL scheme, conformance linter, full menu bar, search and index,
token-based theming.

**Out of scope (v1):** multi-user collaboration, proprietary real-time sync, plugin
ecosystem, HTML rendering of email bodies, contact management, iPad app (later,
view-only), Windows or web versions, full live preview in the editor, the "Forms"
canvas tool.

## Architecture decisions

Taken and not to be reopened without a stated reason (SPEC §14): native SwiftUI over
Electron; macOS 26 Tahoe baseline with no fallbacks; no email body rendering; no full
live preview in v1; pure JSON Canvas 1.0 for the canvas format; harness conventions
as native schema; closed 4-key frontmatter with note IDs living in the index rather
than in files; DTCG design tokens instead of CSS or a webview; infinite recurrences
delegated to Apple Reminders; sync delegated to iCloud Drive; Quick Look not used as
an `.eml` renderer.

Bootstrap decisions: Tuist generates the Xcode project, `Project.swift` is the single
source of truth and the `.xcodeproj` is disposable; Swift Testing rather than XCTest;
bundle id `it.stefer.pergamenum` with automatic signing on team `T7H24G7BFW`.

Still open: the internal module structure, the GRDB schema for the index, and how the
FSEvents watcher reconciles external edits. These belong in
`docs/adr/0001-initial-architecture.md`, to be produced through the `concept-to-code`
chain before M1 implementation starts.

## Milestones

Binding order, each yielding a usable app (SPEC §13):

0. **M0 Design system** - light and dark tokens, Claude mockups of the main views,
   ThemeEngine with runtime theme switching.
1. **M1 Vault + editor** - open the real Labs vault, sidebar, styled markdown editor,
   wikilinks, quick switcher, conformant frontmatter generation, base index.
2. **M2 Workspace base** - board hierarchy with breadcrumb, core toolbar, pan, zoom,
   resize, JSON Canvas round-trip with Obsidian.
3. **M3 PDF and email cards** - PDFKit thumbnails with cache, `.eml` header cards,
   URI cards, To Do and Drawing tools, spacebar Quick Look.
4. **M4 Tasks** - task syntax, task to note and canvas links, Attività views, quick
   rescheduling, quick capture.
5. **M5 Calendar** - daily notes, EventKit read and write, two-way Reminders,
   timeblocking.
6. **M6 URL scheme and conformance** - `pergamenum://` routes, full menus, linter,
   convention import, local notifications.

- The 46 non-conformant notes the linter reports on the real Labs vault: never
  reviewed. The linter reports, it does not correct.

## Decisions closed since the brief was written

- Module boundaries: one app target with folder-enforced layers (ADR-0001).
- The index is the system SQLite in `.pergamenum/cache.db`, not GRDB: four columns do
  not justify a dependency carried for the life of the app.
- FSEvents reconciliation: content hash per file, so an external edit landing mid-write
  is re-read rather than half-indexed.
- `harness-system` is read at a path chosen in the open panel, never assumed.
