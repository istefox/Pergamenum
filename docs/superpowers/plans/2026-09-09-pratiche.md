## Conventions binding on every task

- **The tester owns the interface, the coder owns the body** (ADR-0155 of the
  retired concept-to-code workflow, not a Pergamenum ADR). Swift is compiled: a batch
  that leaves the target unable to build produces a build error, not the red the plan declared.
  Every new type's **declaration** — stored properties, function signatures returning a stub — is
  written in the **tester's** step together with the tests that call it. The coder fills bodies and
  adds no new public surface.
- **Every new source and test file's header cites both `ADR-0036` and this plan's basename**
  (`2026-09-09-pratiche`) — ADR-0154: a harness naming neither is descoped, and the feature's ids
  report `UNSCOPED`.
- **Swift Testing (`@Test`/`#expect`) for all new unit tests.** Never XCTest, except inside
  `UITests/`, which is an XCTest bundle and stays one.
- **One principal type per file. `@Observable`, never `ObservableObject`. No force-unwrap, no
  `try!`.**
- **`tuist generate --no-open` after every task that adds a file under `Sources/` or `Tests/`**, and
  again after any `git` operation that adds or removes a file. The generated project lists what is
  no longer there and the build fails naming the compiler rather than the cause.
- **The unit test command is `.claude/test-cmd` exactly as it stands.** Do not widen it: it runs at
  the end of every turn through the `Stop` hook, and the UI tests in it would terminate the app the
  person at the keyboard is using.
- **`scripts/uitests.sh` runs once, in Task 10, before merge** — never per task, with **no
  argument** (an argument *replaces* the selection rather than adding to it).
- **No test reads `~/Library/Mail`.** `MailStoreLocation.resolve()` is test-aware and returns a
  fixture under xctest even on a host with Full Disk Access (this Mac's terminal has it: a
  `test -e` on the index succeeded on 2026-09-09). Fixture stores are **built by code**, never
  copied from the real store.
- **`sqlite3_` appears in exactly one file**, `Sources/Core/Email/MailStoreConnection.swift`.
  Task 1's test enforces it. A second file reaching for the C API is a stop-and-report.
- **No file under `Sources/Core` or `Sources/Connector` imports AppKit or SwiftUI** (R-38). Both
  connector targets build in Task 5 and again in Task 9.
- **Any shell helper is Bash 3.2-clean.** macOS ships bash 3.2: no `mapfile`, no associative
  arrays, no `${x^^}`/`${x,,}`. `#!/usr/bin/env bash` + `set -euo pipefail`, every variable quoted.
  **`python3`, never `python`.**
- **`weakening-scan.sh` reports every Swift Testing test as `zero-assertion-test`** because it
  treats `#expect` as a comment. Expected, systematically wrong for this stack, advisory.
- **The secret scanner's `assigned-secret` heuristic will fire** on `message_id = "<…>"` lines and
  on base64 fixture payloads. Read every hit; these are message ids and test bytes, not keys.

**Probe results (2026-09-09, batch 1, recorded per this task's own instruction — detail in ADR-0036
«Follow-up — Task 1 probe results»):**

- **C9:** `messages.message_id` is an INTEGER hash. The RFC id is queryable through
  `message_global_data.message_id_header` (96.9% of rows, join on `message_id`), so
  `MailStoreReader.row(forMessageID:)` is implemented there; the ledger covers the rest.
- **C10:** `<V10>/<url host>/<Folder>.mbox[/<Sub>.mbox…]/<store-uuid>/Data/<fan>/Messages/<ROWID>.emlx`,
  fan = `ROWID / 1000` one digit per directory in reverse, empty below 1000; store-uuid read from
  the directory, never derived. Headers-only messages are `<ROWID>.partial.emlx` — Task 2's
  `EMLXLocator` tries that name before `.notInStore` and reports it as `pending` (R-15).
- Dates are Unix epoch seconds. Generation stamp is `max(mtime(index), mtime(-wal))`.

## Risks, dependencies and HITL gates

**Risks.**

- **Reading Mail's store while Mail is writing.** The index ships a `-wal` and is open at all times.
  A file-level copy can be torn between the two `copyItem` calls, and a torn SQLite file does not
  report itself as torn on every query — it reports missing rows. `quick_check` plus one retry
  (ADR §D2) is the whole mitigation, and a sync that reports «Mail sta scrivendo» is the correct
  outcome, not a failure to hide.
- **`.partial.emlx` bodies pending.** 84,194 of the 128,877 files are partial. A first import of a
  long Exchange conversation can be mostly `pending` rows, which will read as "the feature does not
  work" unless the dimmed row and «Apri in Mail» are convincing. R-15 is a UI risk as much as a
  parsing one.
- **The `message://` encoding.** Two encodings exist in this repo today and neither is measured
  against Mail. The wrong one is a subject line that opens nothing, and it will look like a Mail
  problem. Task 2 measures it before anything depends on it.
- **Probing Full Disk Access without a prompt at launch.** macOS does not prompt for FDA, it denies
  silently — so the risk is not a dialog, it is a per-launch touch of somebody's mail store and a
  probe that mistakes "Mail not installed" for "not granted". The probe runs on triggers only, and
  distinguishes `EPERM` from `ENOENT` (R-18 vs «Nessun archivio di Mail trovato»).
- **Performance on 127,818 rows.** An unindexed `sender` or `conversation_id` scan per pratica per
  trigger is a full table scan on every window activation. The indexes created on our own copy
  (ADR §D2) are what make this milliseconds; if that step is skipped the feature will feel broken
  on this Mac specifically, because this Mac is the large case.
- **The same `Message-ID` in Sent and Archive.** All accounts are Exchange, so duplicates across
  mailboxes are the norm, not an edge case. Deduplication happens **before** the first write
  (ADR §D15); after it, the vault has two files and no way to tell which is canonical.
- **A private, undocumented Apple format.** A macOS update can change the schema or the `.emlx`
  layout, and the fixture suite will stay green while acquisition has stopped. There is no early
  warning available; the mitigation is that failures are reported per message rather than swallowed.
- **A copy of the Envelope Index in Application Support** — a few hundred megabytes of mail
  metadata outside `~/Library/Mail`. Regenerable and deletable, and still a widening of where that
  data sits.
- **`.dropDestination` against Mail's file promise is unproven** (R-22) and is a tracer bullet with
  a named fallback, not a commitment.
- **The eleventh Settings tab may collapse the toolbar.** Undocumented threshold, measured once at
  eight tabs / 620 pt. Widen the window; never nest.
- **Eleven panes exhaust the shortcut digits.** Ctrl+Cmd+P is the first pane key that is not a
  digit; the seam is documented in ADR §D8 and nowhere else.

**Dependencies.**

- Full Disk Access granted to the Pergamenum build being run (and never to the UI-test runner).
- Apple Mail installed with a populated `~/Library/Mail/V10/` — present on this Mac.
- Automation (AppleScript) consent for Mail, for the seed path only.
- Tuist 4 + Xcode 26 toolchain, as for every chain here. **No new package.**
  `Tuist/Package.swift` and `Project.swift` are **not** edited.
