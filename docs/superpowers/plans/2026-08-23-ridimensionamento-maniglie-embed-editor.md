### Task 1 — Probe: a non-default `attachmentBounds` really sizes the line (R-01, R-09)

ADR-0019 D8, probe 1. Nothing else may be built until this answers. `EmbedAttachmentProbeTests`
already measured that the override *fires* on a substituted paragraph; it never measured that a
returned rect differing from `image.size` is honoured.

- Extend `Tests/EmbedAttachmentProbeTests.swift` with two tests, one per content type D3 draws:
  a synthetic `NSImage` of 64 × 48 and a PDF first page from the file's existing
  `syntheticPDFFirstPageThumbnail`. Reuse `LoggingAttachment` by giving it an optional
  `forcedBounds: CGSize?`; when set, `attachmentBounds(…)` returns
  `CGRect(origin: .zero, size: forced)` instead of calling `super`.
- **Pass criterion:** with `forcedBounds = 200 × 150`, the embed paragraph's
  `layoutFragmentFrame.height` grows past its height with the unforced attachment, and the
  `bounds` handed to `image(for:bounds:…)` has `size == 200 × 150`. Record the measured numbers
  in the test's own comment, the way every existing probe in that file does.
- **If it fails:** stop and report. ADR-0019 D2 names the two fallbacks in order
  (`attachment.bounds` set from the delegate with the column pushed in; then ADR-0018 §D3's
  custom `NSTextLayoutFragment`), and taking either changes Tasks 3, 5 and 6.
- Budget: Tests/EmbedAttachmentProbeTests.swift (~90 lines)

### Task 2 — `EmbedResize`, the whole grammar and the whole geometry, pure (R-03, R-05, R-06, R-08)

Everything that can be decided without a window. Modelled on `EmbedNavigation` /
`Tests/EmbedNavigationTests.swift`: a pure enum of static functions, no AppKit state, no
`@MainActor`.

Write `Tests/EmbedResizeTests.swift` first, covering:

- **Reading (R-08).** `written(inRun:)` answers `.width(300)` for `![[foto.png|300]]`,
  `.both(300, 200)` for `![[foto.png|300x200]]`, nil for `![[foto.png]]`, nil for
  `![alt](foto.png)` (D7: no sizing syntax was verified for CommonMark), nil for a malformed
  suffix (`|abc`, `|300x`, `|-5`, `|300X200` with a capital X). Leading indentation tolerated,
  the way `embedRun(inLine:)` already tolerates it.
- **Resolving (R-05, R-06).** `resolved(written:natural:column:)`: nil written → natural,
  width-clamped to the column with the height scaled proportionally (R-06's starting size);
  `.width(W)` → `W` clamped to `[80, column]` with a proportional height; `.both(W, H)` → both
  clamped, `H` free of the aspect ratio. Assert the two boundaries explicitly: a request of 10
  yields 80, a request of `column + 500` yields exactly `column`.
- **Writing (R-03).** `suffix(for:natural:)` yields `"300"` when the height is the proportional
  height for 300 within a point after rounding and `"300x200"` when it is not; integers,
  lowercase `x`. `rewritten(run:to:natural:)` replaces an existing suffix rather than appending
  a second (`![[foto.png|300]]` → `![[foto.png|400]]`), adds one where there is none, and
  returns nil for the CommonMark spelling and for a size that resolves to what is already
  written (the zero-movement case D6 sends to `selectEmbed`).
- **The handle's geometry.** `handleRect(in:)` and `handleHitRect(in:)` — a 14-point square
  inset 3 points from the bottom-right corner, and a 22-point square around it. Assert the paint
  rect is contained in the picture frame (ADR-0019 D5's "inside the bounds, never outside", the
  property the accessibility frame depends on) and that the hit rect contains the paint rect.

Then write `Sources/Features/Editor/EmbedResize.swift`: `enum EmbedResize` with
`enum Written { case width(CGFloat); case both(CGFloat, CGFloat) }`,
`enum Phase { case began(CGPoint); case moved(CGPoint); case ended(CGPoint) }`,
`static let minimumSide: CGFloat = 80`, and `static func column(of: NSTextContainer?) -> CGFloat`
returning `size.width - 2 * lineFragmentPadding` — **the only place a column width is computed
in this feature.**

- Budget: Sources/Features/Editor/EmbedResize.swift, Tests/EmbedResizeTests.swift (~340 lines)

### Task 6 — The drag: overlay, live clamp, and not one character written (R-02, R-05)

- Test in `Tests/EmbedCaretTests.swift`, driving the Coordinator directly the way the existing
  click tests drive `selectEmbed(at:in:)` — no `NSEvent` synthesis:
  - `resizeEmbed(.began(p), in:)` returns true for a point inside the handle hit rect and
    **false** for a point elsewhere on the picture (so `onClickInMargin` still gets it and
    `selectEmbed` still selects — the coexistence rule of ADR-0019 D6);
  - after `.began` then `.moved`, `textView.string` is **byte-identical** to what it was
    (**R-02**), and the text view has gained exactly one subview;
  - `.moved` to a point implying a width of 10 leaves the overlay 80 wide, and to a point past
    the right margin leaves it exactly at the column width (**R-05, clamped during the drag**);
  - `.ended` removes the subview.
- Then `CompletingTextView` gains `var onEmbedResize: ((EmbedResize.Phase) -> Bool)?`, and
  `CompletingTextView+Pasteboard.swift` gains `mouseDragged`/`mouseUp` overrides beside the
  existing `mouseDown`. `mouseDown` offers `.began` **before** `onClickInMargin` — order is
  load-bearing, since `selectEmbed` claims the whole picture frame and would swallow the corner.
  All three fall through to `super` when unclaimed.
- Then `NoteTextView.wire(_:to:)` wires `textView.onEmbedResize` to
  `coordinator.resizeEmbed(_:in:)`, closed over `textView` weakly, exactly as `claimsCommand`
  already is at `NoteTextView.swift:207-210`.
- Then `Sources/Features/Editor/EmbedResizeOverlay.swift`: an `NSView` subview of the text view,
  added at `.began`, frame rewritten at `.moved`, removed at `.ended`, drawing the pending
  rectangle's border and `W × H`. Colours and font pushed in at creation from `parent.theme`,
  the way `TranscludedRendition` receives `ruleColor`/`captionColor`. `hitTest(_:)` returns nil.
  It never calls `ThumbnailStore`, never touches `NSTextStorage`, never invalidates layout.
- The drag's state (`run`, picture frame, natural size, grab origin, current size) lives on the
  `Coordinator` as one private struct — not on the view, which stays the dumb forwarder every
  other decoration already treats it as.
- Budget: Sources/Features/Editor/EmbedResizeOverlay.swift, Sources/Features/Editor/NoteTextView+EmbedResize.swift, Sources/Features/Editor/CompletingTextView.swift, Sources/Features/Editor/CompletingTextView+Pasteboard.swift, Sources/Features/Editor/NoteTextView.swift, Tests/EmbedCaretTests.swift (~300 lines)

### Task 7 — The commit: one replacement, one undo step (R-03, R-04)

- Test in `Tests/EmbedCaretTests.swift`, modelled line for line on the existing
  `backspaceAtTheRightEdgeOfADrawnEmbedRemovesItWholeInOneUndoStep`:
  - `.began` → several `.moved` → `.ended` leaves the note reading `![[foto.png|W]]` with the
    expected integer (**R-03**), and `![[foto.png|WxH]]` when the drag changed the ratio;
  - one `undo()` restores the note **exactly** as it was before `.began`, and a second `undo()`
    does not undo more of this gesture, whatever the number of `.moved` steps in between
    (**R-04** — parameterise the test over 1 and 40 moves so the assertion is about the count of
    edits and not about one path);
  - an embed already written `|300` dragged to 400 reads `|400`, not `|300|400`;
  - `.began` immediately followed by `.ended` at the same point writes nothing and leaves the
    run selected (D6's zero-movement case);
  - a CommonMark `![alt](foto.png)` never reaches `.began` at all (D7).
- Then generalise `NoteTextView+EmbedCaret.swift`'s `deleteAtomically(_:in:)` to
  `replaceAtomically(_:with:in:)` — same body, the replacement string parameterised — and have
  the existing deletion at `:63` call it with `""`. **This is the only mechanism the commit may
  use**: `shouldChangeText(inRanges:replacementStrings:)`, then
  `beginEditing`/`replaceCharacters`/`endEditing`, then `didChangeText()`. Do not open an undo
  group by hand, do not call `insertText`, do not write through `parent.text`.
- The `.ended` handler: resolve the final size, format the run with
  `EmbedResize.rewritten(run:to:natural:)`, replace `drawnEmbedRange(atParagraphStart:in:)`'s
  range with it, leave the selection on the rewritten run, remove the overlay. Nil from
  `rewritten` means nothing changed — remove the overlay, select the run, write nothing.
- Budget: Sources/Features/Editor/NoteTextView+EmbedCaret.swift, Sources/Features/Editor/NoteTextView+EmbedResize.swift, Tests/EmbedCaretTests.swift (~220 lines)

## Risks, dependencies and HITL gates

- **HITL before the merge to `main`**, after Task 9 and not before: the branch is a feature
  branch, `main` is never committed to directly, and the UI suite's result is part of what the
  human is approving.
- **HITL before any commit**, per CLAUDE.md. The agent does not commit or push.
- **PR #96 is open, not merged.** It adds `CompletingTextView+Accessibility.swift`, a stored
  property to `CompletingTextView`, and rewrites the `.accessibilityAttachment` lines of
  `embedParagraph(at:storage:)` — all three of which this work also touches. **Decide the order
  before Task 1** and fork this branch from whichever base is chosen. Conflicts are textual, not
  architectural.
- **Task 1 gates everything.** If a non-default `attachmentBounds` return is not honoured, Tasks
  3, 5 and 6 change shape. Stop and report rather than working around it.
- **The missed `mouseUp`.** Pointer leaving the window, window losing key, app switched away
  mid-gesture: `.ended` is the only thing that removes the overlay and writes. Not designed for
  here; looked for in Task 9.
- **`tuist generate --no-open` after every file addition**, and after any `git stash`/`git
  checkout` that moves files — the generated project still lists what is no longer there and the
  build fails naming the compiler rather than the cause.
- **Expected pre-commit noise, not findings:** `weakening-scan.sh` reports every Swift Testing
  test as `zero-assertion-test` (its scanner treats `#expect` as a comment), and the secret
  scanner's `assigned-secret` heuristic fires on design-token lines. Both are documented in
  CLAUDE.md. Read each one before dismissing it; do not silence either scanner.
- **Never disable or weaken a test to make the suite pass.** If a test has to change, say why
  in chat first.
