## Diagnosis (approved in session, 2026-10-01)

Reproduced locally: 1 failure in 40 isolated iterations, and a failure on the first iteration of a
`-run-tests-until-failure` run, same message as CI.

1. `contenitore.selection = other` runs `retireEditor()`
   (`Sources/Features/Contenitore/ContenitoreController+Editing.swift:82-94`), which keeps the
   editor in `retiredEditors` and starts `Task { await old.settle() }`.
2. The test's `settleEditing()` calls `retired.settle()`: the draft differs from the model, so it
   enqueues save T1 and awaits only T1 (`Sources/Features/Contenitore/ContenitoreEditor.swift:86-87`).
3. The retire task runs while T1 is in flight; the model is not updated yet, so it enqueues T2.
4. When T1 ends, `settleEditing()` and T2 both resume, in an order Swift does not guarantee. If
   `settleEditing()` goes first, `saves == 1`, `isSettled` is false, `removeAll { $0.isSettled }`
   keeps the editor and `hasUnsettledEdits` is true.

Production reach: `QuitCoordinator.lastCheck` (`Sources/App/QuitCoordinator.swift:294`) and
`ContenitoreCommand.refusesForOwedEdit` read the same state after `settleEditing()`: a spurious
«Uscita annullata» or a refused rename/move/trash. No data loss.
